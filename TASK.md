# TASK — План реализации

## Задача 1. Структура проекта и основа, данные от брокера
**Что сделать:**
- Создать структуру каталогов: `cmd/dashboard`, `internal/config`, `internal/finam`, `internal/bybit`, `internal/volatility`, `internal/storage`, `internal/ui`.
- Подключить зависимости: `github.com/FinamWeb/finam-trade-api`, `github.com/bybit-exchange/bybit.go.api`, `github.com/rivo/tview`, `modernc.org/sqlite`, `github.com/joho/godotenv`.
- Написать пакет `config` — загрузка `.env`.
- Написать клиенты для Finam (gRPC) и Bybit (REST), которые умеют получать свечи по символу.
- Добавить тесты для расчёта волатильности.

**Как проверить:**
- `go build ./...` — успешно компилируется.
- Юнит-тесты проходят.
- Есть заготовки клиентов, которые можно вызвать из тестов (без реальных сетевых запросов).

## Задача 2. Интерфейс дашборда
**Что сделать:**
- Реализовать главное окно tview с тремя таблицами (Монеты, Акции, Облигации) и таблицей «Прочее».
- Добавить строку поиска и модальное окно для выбора инструмента.
- Обработка клавиш: F5 — обновление, Ctrl+C — выход.
- Отображение ошибок в отдельном окне (без падения).

**Как проверить:**
- Приложение запускается, рисует пустые таблицы.
- При вводе текста в поиск появляется модальное окно (пока с заглушкой).
- Обработка клавиш работает.

**Что сделать:**

- Для Finam — получить свечи через gRPC, для Bybit — через REST.
- Заполнить таблицы данными, окрасить колонку «Торг» по правилам.
- Сохранять результаты в SQLite.

**Как проверить:**
- С реальным токеном и доступом в интернет таблицы заполняются.
- Цвета колонки «Торг» соответствуют диапазонам.
- В БД появляются записи.
